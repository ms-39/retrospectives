# retrospectives

個人開発プロジェクトの振り返り（retrospective）を集めた公開置き場です。
1 つの振り返りを 1 枚の Web ページにまとめ、GitHub Pages で公開します。

## 構成

```
retrospectives/
├── index.html                      # 一覧ページ（新しい順）
├── README.md                       # このファイル
└── <project>/
    └── <YYYY-MM-topic>/
        └── index.html              # 振り返り 1 本 = 単独で読める HTML 1 枚
```

- 例：`kotonoha/2026-10-cc-sdd/index.html`
- 1 本の振り返りは **1 枚の HTML で完結** させる（CSS は中に書く。外部はフォント程度）
- 画像を使うときは同じフォルダに置き、相対パスで参照する
- 各ページの左上などに一覧へ戻るリンク（`../../`）を置く

## 正本と公開版

- **正本はプロジェクトのリポジトリ（非公開）** に置く：`docs/retrospective/<YYYY-MM-topic>/index.html`
- ここ（公開）には、下のチェックを通したものだけを写す
- 直すときは正本を直してから、チェックをやり直してここへ写す

## 振り返りを足す手順

1. プロジェクトのリポジトリで正本を作る（`docs/retrospective/<YYYY-MM-topic>/index.html`）
2. 下の「公開前のチェック」をすべて満たす
3. このリポジトリに `<project>/<YYYY-MM-topic>/index.html` として写す
4. `index.html`（一覧）の `<ul class="list">` の先頭に 1 件足す（日付・題・一文・タグ）
5. ブラウザで一覧と本文を開き、リンクと表示（PC・スマホ幅）を確かめる
6. コミットして push する（数分で Pages に出る）

## 公開前のチェック（毎回・最初のコミットの前に）

公開リポジトリの履歴は消せないものとして扱う。1 つでも引っかかったら公開しない。

**実データ・個人の情報**
- [ ] 実在の人の名前、メールアドレス、生年月日、年齢から特定できる情報がない
- [ ] 記録の中身（発話・メモ・写真・動画・音声）や、それに似せた具体例がない（例は明らかな作り物にする）
- [ ] スクリーンショットに実データ・通知・アカウント名が写っていない

**非公開の情報**
- [ ] 非公開リポジトリの URL、アプリの配信先ドメイン、API のエンドポイントがない
- [ ] AWS のアカウント ID、ARN、バケット名、Cognito のユーザープール ID・`sub`、`family_id` などの識別子がない
- [ ] 鍵・トークン・パスワード・プロファイル名の実値がない
- [ ] HTML のコメントや `<meta>`、画像のメタデータ（位置情報など）にも残っていない

**中身の確かさ**
- [ ] 数字（日数・コミット数・レビュー回数・テスト数など）は、正本のリポジトリで数え直した値で、時点を書いてある
- [ ] 出典の書き方は「プロジェクトのリポジトリ（非公開）より」程度にとどめる

**同意**
- [ ] 家族など、内容に関わる人の了承を得た

確かめ方の例（このリポジトリの中で）：

```sh
# 気になる語がないかをまとめて探す（必要に応じて語を足す）
grep -rniE '@[a-z0-9-]+\.|amazonaws|cloudfront|arn:|[0-9]{12}|family_id|token|password' --include='*.html' .
```

## GitHub Pages の設定

- リポジトリは公開（Public）
- Settings → Pages → Build and deployment：Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にする
- 公開先：`https://<GitHub のユーザー名>.github.io/retrospectives/`
- Jekyll の加工を避けたいときは、空の `.nojekyll` を置く

## ライセンス

文章と図の扱いは各ページに従います。特に書いていないものは、無断での転載をご遠慮ください。
